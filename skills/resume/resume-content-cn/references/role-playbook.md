# 三个内容版本的取材、措辞与结果追问

表中结果是候选人可核实的方向。写有“JD”的例子可在岗位样本表按编号查到；“可追问”是依据工作过程设计的问题，回答之前没有个人成果可供引用。

## 产品经理

共同主线是找到问题、做出取舍、定义方案、协调验证。优先选能还原“为什么选这个方案、谁用、如何知道有效”的经历。纯工具列表无法说明产品判断。

| 分支与依据 | 优先选的个人动作 | 可追问的结果及可用交付 |
|---|---|---|
| AI 应用／搜索，JD01–05 | 标注失败样本并归因，定义能力边界，编写验收规则，比较模型或工作流，复测关键场景 | JD 中出现执行成功、准时送达、评测成本。可追问任务成功率、失败类型是否减少、响应耗时和单位任务成本。有检索标注时才问召回率。无上线数据时写离线评测结论、试点采用范围。 |
| 用户体验／交易，JD06–10 | 经访谈或行为数据定位阻塞，比较交互方案，制作原型，跟进可用性测试 | 任务完成率、完成时间、错误操作次数、上线后使用情况。没有数据可写哪条观察改变了方案、哪项需求进入迭代。 |
| 企业产品，JD11–13 | 访谈业务角色，拆出权限、流程与异常，核对验收条件，跟进试点 | 单笔处理时长、人工步骤、接入团队、流程验收。明确是原型验证、部署还是业务使用。 |
| 增长产品，JD14–18 | 找到流失环节，提出假设，设计对照或分组，观察主指标及副作用 | JD 有登录率、购买率、落地页转化率。追问哪一步到哪一步、实验分流和观察周期；上线前后观察只如实写同期变化。 |

## 运营

共用动作是选定目标人群、安排触达、执行活动或内容、观察行为、按反馈调整。不同岗位主要区别在“运营谁、通过什么手段影响哪一步”。结果按触达→参与→激活／转化→留存选与本人动作最近的一层。

| 分支与依据 | 优先选的个人动作 | 可追问的结果及可用交付 |
|---|---|---|
| AI 运营，JD19–23 | 组织试用、整理失败反馈、调整提示词或使用指引，将高频问题带回产品并验证 | 试用人数、完成首次任务比例、重复使用率、评测耗时、反馈被采纳情况。先判断 JD 偏评测还是偏拉新，再选择指标。 |
| 渠道运营，JD24–27 | 对接合作方，安排渠道排期与物料，拆渠道漏斗，核对线索质量并调整资源 | JD 有线索质量、ROI。可问各渠道有效线索数、有效线索率、获客成本、合作方是否实际启用。只有曝光数据时止于触达。 |
| 媒体／内容运营，JD28–31 | 根据受众定选题，制作与分发图文或视频，用平台后台复盘后调整下一轮 | JD 有曝光、互动率、涨粉和进店转化。区分曝光次数与去重人数；追问渠道、时间窗口、自然／投放流量和账号基数。 |
| 用户／活动运营，JD32–36 | 做人群分层，组织激活或召回，跟踪活动后的实际使用 | JD 有活动参与量、投稿量、作者留存、复购率。提交报名、实际参与、持续活跃分别记录。无指标时写落地的分层规则或后续沿用的流程。 |

## 金融

先区分研究判断和审计核验。研究的成果可以是给某个具体决策提供依据，审计的成果可以是取得支持某一科目核对的证据。两类岗位都适合追问交付物如何被使用。

| 分支与依据 | 优先选的个人动作 | 可追问的结果及可用交付 |
|---|---|---|
| 行研／投研，JD37–43 | 跟踪产业链与公司，验证关键假设，比较标的、搭建或维护估值模型，输出有来源的判断 | JD 有估值模型、研究报告、答辩和路演。可问覆盖多少可比公司、更新多少期、哪项假设影响估值区间、报告用于哪次讨论。报告篇数是产出规模；真实采用另记。 |
| 审计／函证，JD44–53 | 按项目组分工抽查凭证，核对记录，跟踪函证与差异，整理证据索引，编制底稿并提交复核 | 可问已核对样本数、发函／回函数、差异查明数、底稿复核或归档状态。个人整理底稿与项目组出具意见分开表达。“未发现异常”限定在实际检查范围。 |

## 指标口径与追问组件

| 结果概念 | 第三级输入应问什么 |
|---|---|
| 任务成功率 | 哪类任务、成功判定标准、成功数／尝试数、评测集或线上流量？ |
| 召回率／准确率 | 召回率问真实相关项中找回多少；准确率问所有已判断样本中正确多少。正例预测中正确的比例是精确率。记录样本范围与版本。 |
| 转化／激活 | 起点事件、终点事件、同一批用户及窗口；任务数与人数不能混算。 |
| 留存／复购 | 哪批首次使用或购买的人，在第几天或哪个窗口再次做了什么？ |
| 互动率／有效线索率 | 平台以曝光还是触达为分母？有效线索如何认定、分母是否去重？ |
| 获客成本／ROI | 哪些成本、哪批新增客户、收益如何归因？只有投放额和销售额时注明两者比值及口径，不泛称利润回报。 |
| 效率变化 | 同类任务、单位、前后耗时；是实测、估计还是团队反馈？百分比和百分点分开写。 |
| 研究覆盖／采用 | 标的数、数据期、报告接收人和用途；未取得投资组合业绩归因依据时，只写研究交付与使用。 |
| 审计覆盖／差异处理 | 覆盖多少样本、哪个科目；已查明／已提交／已复核分别多少？回函数以同一批发函数为分母，数量不代表审计质量。 |

## 同一事实怎样改写

以下均为虚构教学样例。

**原始材料 A**：“我整理了 30 条试用记录，发现导入文件时有两类报错。我和研发一起列了验收清单；两组同学照着清单又试了一轮。”  
**投产品**：“从 30 条试用记录中归纳两类文件导入错误，与研发明确验收项，两组用户随后按清单复测。”这段的重点是如何把失败案例变成验收条件。  
**投 AI 运营**：“整理 30 条试用反馈，将两类导入问题整理为复测清单，供两组试用者验证。”若 JD 首要职责是提示词评测，这段只证明试用运营；应优先检索是否另有评测样本和优化记录。

**原始材料 B**：“我把三个渠道报名名单去重，发现其中一个有很多重复提交；下次报名用了我做的核对表。”  
**投渠道运营**：“核对三个渠道的报名名单，定位重复提交通道并制作核对表，供下一轮报名复用。”可追问重复比例，已确认的复用足以作为阶段成果。

**原始材料 C**：“课程研究里，我查了五家公司的年报，把不同口径的毛利率列了备注，在答辩时解释了为什么剔除其中一家。”  
**投行研**：“对照五家公司的年报核查毛利率口径，在答辩中说明一家公司不宜纳入可比组的依据。”  
**投审计**：可作为核对口径的相近经历，保留“课程研究”。若经历库另有抽凭或底稿记录，优先展开后者。例如材料为“在项目组指导下核对采购凭证，列出三处差异并提交复核”，成文可写“核对采购凭证，将三处差异及对应单据整理成清单，提交项目组复核”。只有回传处理结果才写“已查明”。
