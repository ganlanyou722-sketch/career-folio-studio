# 中文简历内容优化

接收目标 JD、已确认的经历事实及可选的现有简历。输出经历取舍、可直接应用的条目、待核实的结果问题。版面沿用当前简历。产品经理场景可与 chinese-product-manager-cv 排版规则配合。

1. 把目标 JD 拆为具体职责、明确必需、加分项、通用任职条件。逐条保留原句。用实际职责选[岗位分支](references/role-playbook.md)。一个岗位同时写“增长”和“AI”，可选一个主分支、一个辅助分支；同时投两个岗位则生成两套独立排序。缺具体 JD 时按用户选定方向处理，标注“方向初稿”。
2. 每段经历拆出事实单元，记录事实 ID、原文位置或本人确认、服务对象、个人动作、判断、交付物、结果、阶段与归属。材料只有项目介绍时先问“你具体做了哪一步？”。
3. 建立“岗位要求 → 事实 ID → 原始证据 → 匹配理由”。按工作对象、任务、方法与交付物判断直接或可迁移支持。先覆盖最核心职责，再覆盖其他要求。同等相关时优先本人动作明确、有结果或交付证据的经历；互补证据优先于重复证据。无匹配时列缺口。竞赛、课程、论文与实习按同一标准；选择后沿用模板的栏内时间顺序，在每段内把相关贡献前置。
4. 为用户标明“重点展开／压缩保留／本版略去”及一句理由。已有简历默认只重排要点、替换泛词、补入已确认事实；在同一份简历当前稿上返回逐条修改建议。新手先搭完整初稿，缺 R 的核心条目附一张追问卡。
5. 逐条写作：确定一个贡献主题，选能说明此人做了什么的动词，交代对象和关键判断，接上交付或经证实的后续变化。产品写取舍，运营写干预，研究写依据，审计写程序及证据。一次改写保留可还原到事实的词。保留“协助／参与／独立负责”、团队与个人、离线与线上、提交与采用等边界。
6. 用[指标与追问](references/role-playbook.md)选最多三个候选 R，再走“有量化／暂无量化 → 指标或事件 → 值、范围、实际状态”。确无数据，优先问交付去向；主管认可只在本人确认具体反馈后使用。用户可跳过。数据未确认时返回草稿标记，不将猜测写入可投递正文。
7. 交付每条的原句、建议句、目标职责、事实 ID、选用理由及待补项。词库命中只帮助召回材料。JD 中的资格证、软件、ROI、召回率都需单独核实，不能充当候选人的经历。

## 词库

[岗位样本与出处](references/jd-index.md)供人工核对。[JSON 词库](assets/jd-keywords.json)的 sources 保存岗位与所选原词，keywords 是词到岗位的倒排索引。优先查本次 JD，再找同分支表达。相似词可扩展检索，例如“底稿编制／工作底稿”“提示词／Prompt”“需求文档／PRD”；成文采用本人实际用过的方法。盘点与监盘、曝光与触达、准确率与召回率、估值与盈利预测分别保留语义。
